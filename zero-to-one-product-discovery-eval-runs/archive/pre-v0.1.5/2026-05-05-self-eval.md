## Findings

### Strengths

- Trigger and non-trigger boundaries are explicit.
- Diagnostic Start prevents premature PRD, Roadmap, ADR, tech stack, and MVP scope.
- Existing PRD or feedback without MVP remains inside this skill, with Material Assimilation as the next step.
- Design references are preserved for later stages instead of driving early discovery.
- Open-source and resume goals are preserved as evaluation constraints.

### Weaknesses

- Heavy Advisor mode could still over-produce complete artifacts if the product domain is under-specified.
- Existing-material scenarios need a clearer rule that "please provide or point me to the material" can be the one allowed high-leverage question.
- Length control is present in the eval rubric but not in `SKILL.md`; future responses may become longer than intended.

### Required Patches

- Add a Heavy Advisor guardrail: if the domain is under-specified, produce artifact outlines and decision surfaces, not complete PRD/Roadmap/ADR content.
- Add a Material Assimilation question rule: when materials exist but are not provided, the single high-leverage question may ask the user to provide or identify the material to inspect.
- Consider adding a Diagnostic Start target length hint to `SKILL.md`.

### Follow-up Scenarios

- User provides a long PRD and asks for direct rewrite.
- User has a clickable prototype but no validated workflow.
- User asks for "make this idea into a startup" with monetization pressure.
- User asks for an app idea mainly driven by visual references.
- User explicitly asks to revisit an existing MVP from first principles.
